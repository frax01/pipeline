# Validazione manuale — rirun

Stessa metodologia di [MANUAL.md](../MANUAL.md) e [MANUAL_CHECKLIST.md](../MANUAL_CHECKLIST.md): campione stratificato per server, verdetto deciso leggendo il **codice sorgente reale** preso da GitHub (o, per le categorie il cui entry point e' la descrizione del tool, la descrizione stessa).

Formato del verdetto: `VERDETTO_MANUALE (verdetto_pipeline)`.

| Sigla | Significato |
|-------|-------------|
| **VP-C** | Vero Positivo Confermato — vulnerabilita' sfruttabile sul codice attuale |
| **VP-L** | Vero Positivo Latente / by-design — capability dichiarata del server |
| **VP-D** | Vero Positivo Debole — pattern reale ma blast radius limitato |
| **FP**   | Falso Positivo — pattern matchato ma codice benigno |
| **n/d**  | Non determinabile — repo o file non piu' recuperabile |

> Differenza dichiarata rispetto alla prima analisi: il criterio del *parameter binding* non e' stato usato, su indicazione dell'autore, perche' non faceva parte del processo originale.
