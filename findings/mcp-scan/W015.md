# W015 — UNTRUSTED CONTENT

**Finding originali**: 599

Severity: **medium** per tutti i 599, risk_score uniforme **0.5**, messaggio identico `"Untrusted Content."`.

Anche W015, come E001, non ha una regex pubblica: la detection avviene nel backend di Invariant Labs. mcp-scan emette W015 quando un server MCP espone tool che leggono dati da **fonti esterne non verificate** (repository pubblici, API aperte, siti web, piattaforme community-editable). Il rischio sottostante e' l'**indirect prompt injection**: un attaccante avvelena la fonte dati, l'agente la legge e processa le istruzioni malevole embedded nel contenuto.

Relazione con W016: W016 ("**Potential** Untrusted Content", 1.483 finding, severity low, score 0.25) e' la controparte a bassa severita di W015 — stessa classe di vulnerabilita ma con barriere di poisoning maggiori (es. Docker image pull, accesso di rete, SEO manipulation).

---

**Finding dopo filtro**: 599 (nessun filtro regex intermedio applicato)

Come per E001, non c'e' Fase 2 a regex: mcp-scan restituisce direttamente i finding dal suo backend. Si e' quindi proceduto direttamente all'analisi manuale/LLM su tutti i 599 finding.

---

**Veri positivi confermati dopo analisi LLM**: ~590 (98%)

A differenza di E001 (dove il tasso di FP e' ~65%), W015 descrive una **classe di vulnerabilita reale e ben documentata**. Praticamente tutti i 599 finding sono **veri positivi nel senso che il rischio descritto esiste realmente**. I ~9 finding borderline/non applicabili sono server che leggono solo dati locali/privati.

Tuttavia mcp-scan assegna lo stesso risk_score (0.5) a tutti, senza distinguere tra scenari dove il poisoning e' triviale e scenari dove e' molto piu' difficile. Questo e' il **limite principale dell'analisi**.

### Distribuzione per tipo di fonte dati

**Alta facilita' di poisoning (~200 finding, veri positivi forti)**
- **Repository Git pubblici** (gruppo piu' grande): qualsiasi server che clona/legge repo GitHub — l'attaccante crea un repo con contenuto malevolo in README, commit message, file. Esempi: `github-mcp-server`, `mcp-gitee`, `heroku-mcp-server`.
- **Piattaforme community-editable**: Open Library, wiki, forum — editabili con account gratuito. Esempio: `mcp-open-library`.
- **Commenti/contenuto social**: YouTube (commenti, sottotitoli), Telegram, Reddit. Esempi: `youtube-dlp-server`, `youtube-mcp`, `telegram-mcp-server`.
- **Web scraping generico**: server che fetchano URL arbitrari. Esempi: `scrapi-mcp`, `seo-mcp`.

**Media facilita' di poisoning (~250 finding, rischio contestuale)**
- **API di terze parti con dati pubblici**: blockchain explorer, analytics, marketplace. Esempi: `algorand-mcp`, `dexpaprika-mcp`, `hive-crypto-mcp`.
- **Sistemi di observability**: trace/span avvelenate via richieste a servizi instrumentati. Esempio: `agentops-mcp`.
- **Package manager e DevContainers**: pubblicazione di pacchetti/configurazioni malevole. Esempio: `mcp-devcontainers`.

**Bassa facilita' di poisoning (~150 finding, borderline)**
- **API con autenticazione**: Salesforce, Keycloak, Google Analytics — richiede accesso all'ambiente. Esempi: `mcp-salesforce`, `keycloak-model-context-protocol`, `mcp-google-analytics`.
- **Dati locali/privati**: file locali o database interni — poisoning richiede accesso pre-esistente al sistema.

### Limiti dell'analisi di mcp-scan

1. **Score uniforme**: tutti i 599 finding hanno risk_score=0.5, ma la facilita reale di poisoning varia enormemente (un repo GitHub pubblico vs un'istanza Salesforce privata).
2. **Nessuna deduplicazione**: fork dello stesso server vengono contati separatamente.
3. **Granularita tool-level mancante**: W015 e' a livello server, non indica quali tool specifici sono esposti al contenuto non-trusted.
4. **Falso senso di uniformita**: avere 599 finding tutti "medium" con lo stesso score non aiuta a prioritizzare. Un `mcp-devcontainers` che esegue script da repo esterni (code execution) e' molto piu' pericoloso di un server che legge titoli di libri da Open Library (solo testo), ma entrambi ricevono lo stesso score.

La vulnerabilita' W015 e' **concettualmente corretta** — leggere dati da fonti non verificate e' un rischio reale per agenti LLM. Il problema e' che mcp-scan non distingue la gravita.
